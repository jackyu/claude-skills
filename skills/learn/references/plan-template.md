# 計畫模板（plan.md）

10 課、每課一個小主題、每課約 2 小時。排序：先排後面所有東西都建在它上面的，再排可驗證成果直接需要的。

```markdown
# <主題>：20% 計畫（10 課）

目標：<期限> 前做出 <可驗證成果>
為什麼是這 10 個：<2–3 句，說明捨掉了什麼、為什麼捨>

| 課 | slug | 等級 | 小主題 | 這課要會 | 課後那一題／那個任務 |
|---|---|---|---|---|---|
| 1 | variables-types | L1 | 變數與基本型別 | 分得清 list／tuple／dict 何時用哪個 | 寫一段程式把 CSV 一列轉成 dict |
| 2 | functions | L1 | 函式與參數 | 預設參數的陷阱 | 解釋 `def f(x=[])` 為什麼會累積 |
| 3 | … | | | | |
| 10 | … | L4 | | | 交出可驗證成果的第一版 |

## 不在這 10 課裡的（之後再說）

- <被捨掉的主題>：<一句為什麼現在不學>
```

## 取捨原則

- `slug` 是 kebab-case 英文，之後速查表檔名就用它。
- 「這課要會」寫一件事，寫兩件就拆課。
- 課後那一題要跟階梯的過關標準對得上，最後一課的任務就是目標成果。
- 「不在這 10 課裡的」一定要寫，這是帕累托法則真正發揮作用的地方。
