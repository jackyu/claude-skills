# PM 口吻用詞規則

判準：**德信審核人員或業務主管讀這句，需不需要問 RD 才懂？** 需要就改。

## 寫「誰看到什麼」，不寫「系統怎麼做」

| 不要寫 | 改寫成 |
| --- | --- |
| 新增 API 欄位回傳寄信狀態 | 案件列表上看得出這件寄過信沒 |
| 前端加 confirm dialog | 寄出前跳出確認視窗，顯示信件類型和收件 Email |
| status 改為 PENDING_NOTICE | 案件狀態顯示「待寄送通知」 |
| 寫入 DB log | 案件紀錄留下寄送時間和操作人員 |
| 回傳 400 錯誤 | 畫面顯示「<實際訊息>」，資料不會送出 |
| 系統正確處理 | 寫出處理完的具體結果（收到信、狀態變成什麼） |

## 禁用詞（出現就改寫）

- 技術名詞：API、endpoint、欄位（改「資料」「項目」）、component、元件、state、狀態碼、mutation、refetch、cache、DB、資料庫、table、payload、request、response、token、flag、enum、trigger、webhook、cron、前端、後端
- 中國用語：默認（→預設）、調用（→使用）、接口（→介面／串接）、質量（→品質）、用戶體驗閉環、兜底、賦能、抓手
- 空泛詞：優化（講改了什麼）、相關（講是哪個）、進行（直接寫動作）、等等（列完或寫「以上幾種」）、儘速（寫期限）、適當地

例外：業務本來就在用的詞照用，例如 B27、KYC、AML、中信、交割帳戶、營業員、退件、銷件、案件狀態（畫面上看得到的「待審核」「已退件」這類）。「系統會…」只用在真的自動發生、沒人操作的事。拿不準就在第一次出現時補一句白話說明。

## 句子

- 一句講一件事，超過 40 字就拆。
- 主詞寫清楚是誰：「後台人員」「客戶」「主管」，不寫「系統會」除非真的是自動發生的事。
- 數字寫死：「90 天」「三個工作天」，不寫「一段時間」。
- 用台灣日常講法；稱呼開戶的人用「客戶」或「用戶」，同一張票統一一種。
