# FE MR Digest

> 將已合併的 GitLab MR 轉化為學習筆記

## Purpose

從已合併的 MR 中萃取學習價值，產出淺顯易懂的學習筆記。本 skill 的本質是「學」而非「審」——目標是理解資深工程師的思路、技巧與決策，並從 Reviewer 的回饋中學習。所有內容假設讀者是 1-2 年經驗的前端工程師，技術概念首次出現時皆附上一句話解釋。

## When to Use

- 用戶要求將 MR 整理成學習筆記
- 用戶提到 MR 學習、MR 筆記、MR digest
- 用戶想從某個 MR 學習工程師的思路或技巧
- 用戶提到從 code review 中學習
- 用戶想把 MR 當作教材或知識庫素材
- 用戶說「這個 MR 寫得不錯，幫我整理一下」
- 用戶說「幫我看看這個 MR 有什麼值得學的」

## Key Features

- **學習導向**：聚焦在「做了什麼、怎麼做的、為什麼這樣做、Reviewer 怎麼看」四個維度
- **設計意圖萃取**：辨識變更類型（新功能 / 重構 / Bug fix / 效能 / 基礎設施），對應不同學習重點
- **Review 對話保留**：擷取有學習價值的討論串，保留問答脈絡並補上「📖 學到什麼」總結
- **替代方案推敲**：從討論與註解中還原「為什麼不這樣做」，避免無中生有
- **難度分級與標籤**：🟢 初階 / 🟡 中階 / 🔴 進階，搭配 12 種預設學習標籤
- **流程圖判斷**：僅在資料流變化、狀態流轉、請求流程時才產出 Mermaid 圖
- **段落取捨**：依 MR 內容動態決定哪些段落出現，避免硬湊
- **特殊情境處理**：MR 描述過於簡略、沒有 Review、超大型 MR 各有對應策略
- **中文文案排版規範**（中英文間距、全形標點等）

## Workflow

1. 透過 `mr-context.sh --all-discussions` 取得 MR 基本資訊、合併狀態、Diff 與 Review 討論
2. 仔細閱讀 MR description 作為筆記骨幹
3. 分析 diff，辨識變更類型並萃取技巧與設計決策
4. 識別 Before / After 對比機會（限重構/優化類 MR）
5. 從 Review 討論擷取有學習價值的對話，保留問答脈絡
6. 推敲「為什麼不這樣做」的替代方案
7. 判斷是否需要流程圖（資料流 / 狀態機 / 時序圖）
8. 評估難度分級並標記學習標籤
9. 依模板產出繁體中文 Markdown 學習筆記
