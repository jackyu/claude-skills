# comment-polish

整批掃描並改寫程式碼中的既有註解，去除翻譯腔與 AI 贅字，改成口語但專業的表達。

## 解決什麼問題

AI 產出或翻譯腔濃厚的註解讀起來費力：「此處進行防禦性檢查以確保資料完整性」這種句子，同事在 code review 根本不會這樣講。這個 skill 把既有註解整批改成自然的講法：「先擋掉空值，後面才不用一直判斷」。

## 改寫判準

以 `~/.claude/rules/comment-style.md` 為單一真相來源（該檔不存在時用 SKILL.md 內建的濃縮版）：

- **口語但專業**——像 code review 留言，不帶玩笑或語氣詞
- **行為描述**取代名詞化黑話
- 單句**超過 40 字拆開**重組
- 砍贅字（此處、進行、用於、以確保……）
- 避開中國用語（質量、默認、調用、接口……）

## 工作流程

| Step | 動作 |
|---|---|
| 1 | 確定範圍：分支 diff／指定目錄／整個專案（未指定先問） |
| 2 | 掃描註解，記下 `檔案:行號`；範圍大時派 subagent |
| 3 | 產出 before/after 改寫清單（只列需要改的） |
| 4 | 用戶核可（可挑選部分）後才套用 |
| 5 | `git diff` 驗證只有註解行變動，跑 type-check 防呆 |

## 安全邊界

- **只動註解文字**：程式邏輯、字串、識別字一律不碰
- **不刪不增**：不刪整條註解、不加新註解——註解該不該存在不是此 skill 的事
- **跳過不碰**：commented-out code、license header、`eslint-disable` 等工具指令、`TODO:`/`FIXME:` 標籤、JSDoc 結構標籤
- **未經核可不改檔**：清單核可前不動任何檔案

## 安裝

```bash
./scripts/install.sh -s comment-polish
```
