# 可達性複核與操作證據

每筆候選 finding 都照這份判定。這是唯一的一份：Codex 的 `codex-evidence-review` 透過 symlink（`references/reachability.md`）讀同一個檔，改規則只改這裡。

## 一、實務操作可達性複核

每個候選問題在列為 finding 或判定阻擋合併前，將技術觸發序列改寫成實務使用者能理解的完整流程，再逐步挑戰：

1. **從實際入口走到結果**：寫明角色、起始頁面／狀態、操作、等待期間、下一步操作與可觀察的損害。不能跳過「使用者如何到達這個狀態」，或用直接改 props、store、URL 代替實際操作而不揭露。非互動問題則追真實的背景事件、外部輸入或公開 API 呼叫者。
2. **檢查操作當下的防護**：沿 UI、呼叫端、共用模組與後端查遮罩、modal、disabled、導航限制、取消請求、識別檢查及冪等處理。說明哪一層何時生效、是否阻斷必要步驟；例如送單等待期間若全畫面遮罩擋住切換，就不能直接假設使用者能切分頁並編輯下一筆。也不能只看到遮罩便宣稱所有輸入路徑皆被封鎖，須檢查與候選流程相關的實際操作方式。
3. **核對元件生命週期**：區分同一元件 rerender、卸載後重新掛載、路由換頁與 query string 更新。測試若保留元件但實際路由會卸載，或反過來，不能沿用其結論；框架行為不確定時標示缺口，按需做瀏覽器驗證。
4. **檢查人類操作與時序是否可行**：列出必要動作、可用時間窗口，以及窗口的起訖（事件處理、render／commit、遮罩生效或回應到達）。若假設須在 100 毫秒內完成辨識、導航、切換並輸入等多步操作，需提出可行操作或實測依據；不能把同一個 `act`、直接連續呼叫 handler、強制點擊或任意暫停程式，當成真人能做到的證據。也不設「小於 100 毫秒必不可能」的通用門檻：單一快速連點、已排入的事件、程式自動觸發及慢網路拉長窗口，應依實際路徑判斷，不能只靠直覺排除競態。
5. **用反證裁決**：若必要操作已被證實阻斷，且沒有具體的其他可達入口，撤銷該產品 bug 假設，必要時另列非阻擋的防禦性建議。若仍缺可達性證據，標示「底層行為已重現；實務觸發待驗證」，附最小下一步，不直接列為已確認的阻擋缺陷；也不能把未知寫成「實際不可能」。若真實流程仍可達，保留 finding，說明防護為何不足。

可達性與發生頻率分開判斷。罕見但可達且有實際損害的問題仍可能需要修正；高影響但可達性未明者可列為合併前待確認事項，是否暫無法判定須說明理由。共用／公開模組若另有獨立契約或其他真實消費者，應另外驗證其違約影響，不能僅憑某一頁的遮罩排除整個模組的問題。安全問題依攻擊者可控制的入口判斷，不以一般使用者的 UI 限制代替後端防護。

例如「晚到的 reset 清掉新設定」：先分別驗證卸載後重建與持續掛載的行為，再查送單等待期間能否切換、編輯，以及實際切換是否保留元件。只有 hook 測試失敗時，結論限於 hook；確認上述完整流程可達後，才稱為使用者會遇到的錯誤。

## 二、確認可達後，提供人類可照做的操作證據

對 UI 操作可觸發的確認缺陷，在 finding 中用有順序的具體步驟交代：

- **起始條件**：角色／帳戶、頁面、必要設定與資料狀態，只列觸發所需條件。
- **操作順序**：使用畫面可辨識的按鈕、欄位、分頁名稱，寫清點哪裡、輸入什麼、等待什麼，再做什麼；不以函式名或「觸發競態」代替操作。
- **關鍵時機與可行性**：若需在回應前操作，說明當時畫面顯示什麼、如何辨識時機、為何仍可操作，以及已查到的遮罩／disabled 等防護為何未阻斷。依賴延遲、特定資料或特定設定時明列，若用限速模擬則揭露，不能冒稱一般網路下已重現。
- **可觀察結果**：分開描述預期行為與實際錯誤，使用具體值或狀態變化，連結到使用者損害。
- **佐證層級**：實際 UI 重現時附環境、結果及可用的截圖／錄影／日誌；僅由程式控制流證實時，附操作對應的入口與防護證據，明說尚未在 UI 實跑。無法寫出完整可行步驟時，回到待驗證，不補造操作流程。

步驟以真人可完成的操作為準；測試工具的強制點擊、直接寫 store 或呼叫 callback 應另列為診斷方式。非 UI 問題則提供等價的真實事件／API 輸入序列，不硬編成使用者點擊。流程簡單時可用短段落，需精確先後或時序時用編號清單，避免把證據埋在技術分析裡。

## 三、重現層級

| 層級 | 意思 |
|---|---|
| 函式 | 直接呼叫純函式或工具 |
| hook | renderHook、直接操作 store |
| 整合 | 頁面或元件測試，用使用者事件操作 |
| 實際 UI | 真瀏覽器（verify-admin／verify-client drive）走真實入口 |

底層重現不自動證明產品可達。既有測試與實際 UI 的生命週期、防護或時序不同時，寫出差異。
