# 難度分級

依以下標準判斷 MR 的複雜度，協助讀者快速評估投入時間。

| 等級 | 標準 | 典型主題 |
|---|---|---|
| 🟢 初階 | 單一檔案修改、單純的 UI 調整、基礎 Hook 使用 | 樣式修正、props 傳遞、基礎 state 管理 |
| 🟡 中階 | 跨元件的邏輯、Custom Hook、API 串接、狀態管理 | 表單處理、資料 fetching、共用元件設計 |
| 🔴 進階 | 架構設計、效能優化、複雜的型別設計、跨模組重構 | 設計模式應用、渲染優化、大規模重構策略 |

## 判斷技巧

- 看「**讀懂變更需要的前置知識**」而非「行數」：500 行樣式 patch 是 🟢，30 行的狀態機重構可能是 🔴。
- 看「**改動範圍**」：單一檔案 vs 跨模組 → 是否需要理解多處互動。
- 看「**對既有抽象的衝擊**」：是否引入新概念、是否改變了既有 API 的形狀。

## 邊界情況

混合型 MR 取「最高難度的部分」標記，並在說明中註記「主要難度落在 X 段落」。
