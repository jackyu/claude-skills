# 交出前自檢

八點自檢，編號對齊 `a3-grid.md` 的八格。逐點打 ✅ 或 ⚠️，結果做成閘門表放在輸出末尾。

## 八點

| 檢查點 | 過關條件 |
|---|---|
| ① 問題是否具體、可驗證 | 一句話說得出誰痛、痛在哪，沒混進解法 |
| ② 現況數字是否有來源 | 數字齊全且都能對回事實清單才 ✅；有任何一項待確認就 ⚠️，說明欄指向該待確認項 |
| ③ 目標是否有期限與指標 | 有指標、有數字、有期限，不是「提升體驗」這種 |
| ④ 根因是否可驗證 | 因果鏈每一節有佐證，沒佐證的已標 🟡 或 🔴 |
| ⑤ 對策是否比較過至少兩個方案 | 四欄表的效益與風險或成本都填了，建議欄有理由 |
| ⑥ 計畫每項是否有負責人與日期 | 沒有「近期」「儘速」這種假精確 |
| ⑦ 成效是否有量測方式與基準值 | 數字齊全且都能對回事實清單才 ✅；有任何一項待確認就 ⚠️，說明欄指向該待確認項 |
| ⑧ 標準化是否有具體規則與 owner | 說得出怎麼避免復發、誰負責維持 |

## 各模式套哪幾點

| 模式 | 套哪幾點 |
|---|---|
| `weekly` | 固定四點 ①②⑤⑥，② 一列同時涵蓋拍板事項的現況數字與進度數字 |
| `proposal` | 八點全套 |

## 閘門表格式

固定三欄，固定放在輸出最末尾：

| 檢查點 | 結果 | 說明 |
|---|---|---|

- 檢查點欄逐字用上表的名稱，含 ①–⑧ 編號。
- 結果欄只放 ✅ 或 ⚠️，不放其他符號。
- 說明欄：✅ 寫一句話交代怎麼過的；⚠️ 必須指向對應的待確認項，讓主管知道去哪看。

範例（`weekly`）：

| 檢查點 | 結果 | 說明 |
|---|---|---|
| ① 問題是否具體、可驗證 | ✅ | 拍板 1、拍板 2 都一句話講清楚誰痛、痛在哪 |
| ② 現況數字是否有來源 | ⚠️ | 結帳頁錯誤率沒數據，見「拍板 2 現況」的 🔴 待確認 |
| ⑤ 對策是否比較過至少兩個方案 | ✅ | 拍板 1、拍板 2 各列了三個方案含「什麼都不做」 |
| ⑥ 計畫每項是否有負責人與日期 | ⚠️ | 「補結帳 e2e 測試」還沒指定負責人，見「下週」第 3 項 |

## ⚠️ 的處置

1. **先修。** 素材裡其實有、只是沒寫進去，補進去改成 ✅。
2. **修不了就改標待確認。** 用固定寫法 `🔴 待確認：<缺什麼>，去哪拿：<…>`，閘門表說明欄指向那一項，然後交出去。
3. **不准靜默略過。** 沒把握的項目就是 ⚠️，不要因為看起來不重要就打 ✅。
4. **不准為了全 ✅ 刪內容。** 把有疑慮的段落刪掉來換 ✅ 是最糟的做法，主管會在會議上才發現這個洞。

閘門表全 ✅ 時也要保留表格，那是「我檢查過了」的證據，不是可有可無的裝飾。
