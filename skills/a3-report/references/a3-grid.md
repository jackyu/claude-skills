# A3 八格：每格寫什麼

豐田 A3 報告的一頁八格。左半抓問題（①–④），右半解問題（⑤–⑧）。`proposal` 模式用完整八格，`weekly` 模式只借其中五項組成「拍板事項」（見文末對應表）。

## 八格定義

| 格 | 名稱 | 一句話定義 |
|---|---|---|
| ① | 問題 | 誰在痛、痛在哪，一句話講完，不寫解法 |
| ② | 現況 | 現在實際長怎樣，用數字說話，每個數字附來源 |
| ③ | 目標 | 做完之後量到什麼數字才算成功，含期限 |
| ④ | 根因 | 為什麼會這樣，一條可驗證的因果鏈，不是猜測 |
| ⑤ | 對策 | 打算怎麼做，至少兩個方案擺出來比 |
| ⑥ | 計畫 | 誰在什麼時候做完哪一段，里程碑表 |
| ⑦ | 成效 | 用什麼數字確認有效、什麼時候量、基準值多少 |
| ⑧ | 標準化 | 怎麼避免復發：規則、自動化、owner |

## 每格的寫法：一句結論再條列

每一格開頭先寫一句話結論，主管只讀這句也能懂。條列放在結論下面當佐證，一格不超過五條。

範例（② 現況）：

```
結論：結帳頁載入要 4.2 秒，是全站最慢的一頁。
- 首屏渲染 4.2s（來源：GA Web Vitals，2026-08 月均）
- 其中 2.8s 花在等三支序列打的 API（來源：MR !312 的 profiling 附圖）
- 同期結帳流失率 18%（來源：GA 漏斗）
```

反例：一格塞十條，沒有結論句，主管得自己讀完歸納。

## ② 現況與 ⑦ 成效的數字硬規則

這兩格是主管拿來做決定的依據，規則比其他格嚴：

1. **每個數字都要能對回事實清單。** 對不回去就不准寫進去。
2. 對不回去但這個數字很關鍵，改寫成待確認：`🔴 待確認：結帳頁的實際錯誤率，去哪拿：Sentry 專案 checkout-web 的 2026-08 統計`
3. 不准寫「約」「大幅」「明顯改善」這種沒有數字的形容。要嘛有數字，要嘛標待確認。
4. ⑦ 成效在提案階段還沒發生，寫的是「打算怎麼量」：指標、量測時間點、目前基準值。基準值缺就標待確認。
5. 數字要附來源標記，格式跟事實清單一致（`[筆記]`／`[issue #N]`／`[MR !N]`／外部 dashboard 名稱）。

## 信心標記

沿用 `../fe-mr-walkthrough/SKILL.md` 的信心三級（見「AI 扮演作者的信心三級」一節）：

| 標記 | 意思 | 寫法 |
|---|---|---|
| 🟢 | 事實清單裡有直接佐證 | 直接寫，附來源 |
| 🟡 | 推測 | 寫「我的理解是…」並附推測依據 |
| 🔴 | 待確認 | 用下面的固定寫法 |

🔴 與「待確認」是同一件事，不另設第四級。

**待確認固定寫法：**

```
🔴 待確認：<缺什麼>，去哪拿：<Sentry／GA／某 dashboard／問誰>
```

「去哪拿」不准留空，也不准寫『同上』『見上方』，每一條自己寫完整。不知道去哪拿就寫「去哪拿：問 PM 或 SRE 確認有沒有這份數據」。

**禁止偽造引用。** 不准寫「PM 說」「主管說」「後端表示」這類話，除非事實清單裡有原文。要引述就標來源。

## ⑤ 對策的方案比較表

固定四欄，四欄是排版上限（見 `../_shared/fe-mr-common/writing-principles.md` 結構排版一節）：

| 方案 | 效益 | 風險或成本 | 建議 |
|---|---|---|---|

- 至少兩個方案，包含「什麼都不做」也算一個方案。
- 效益寫得到什麼，風險或成本寫要付出什麼、可能壞在哪，兩欄都不准空白。
- 建議欄只寫「選／不選」加半句理由，長理由寫在表格下面。

## ④ 根因的因果鏈

寫成可驗證的一條鏈，每一節都要有事實清單佐證：

```
結帳慢 → 三支 API 序列打 → 前一支的 token 被下一支當參數用 → 當初為了趕上線沒拆 → [MR !198 的討論串]
```

鏈上任何一節沒有佐證，那一節標 🟡 並寫推測依據。整條鏈都沒佐證就不要寫這格，改標 🔴 待確認。

## 一頁放不下怎麼辦

八格擠在一頁是刻意的限制，逼你篩掉不影響決定的東西。放不下時：

1. 影響決策的留主體：問題、方案比較、要主管決定什麼、期限。
2. 其餘移到附錄：完整 MR／issue 清單、細節數據、過程紀錄。
3. 不准縮小字級硬塞，也不准刪掉待確認項來騰空間。

## 縮小版 A3：拍板事項怎麼從八格縮成五項

`weekly` 模式的每個拍板事項套 `assets/decision-item-template.md`，五項與八格的對應：

| 拍板事項的項目 | 對應的格 | 說明 |
|---|---|---|
| 問題 | ① | 一句話，誰痛、痛在哪 |
| 現況 | ② | 數字事實，硬規則照舊 |
| 方案比較 | ⑤ | 同一張四欄表 |
| 建議 | ⑤ | 選哪個、為什麼 |
| 要主管決定什麼 | ③ ＋ ⑥ | 取 ③ 的期限與 ⑥ 的「不決定會卡住誰」 |

沒對到的 ④ 根因、⑦ 成效、⑧ 標準化，拍板事項不套。這三格是提案要交代的深度，週報的拍板事項不需要，硬寫會變成湊格式。

真的需要交代根因與成效，代表這件事已經是提案等級，改用 `proposal` 模式寫完整八格。
