# Code Review 輸出格式範本

使用繁體中文，Markdown 格式，依下列結構產出最終報告。

**撰寫前提**：讀者可能不熟悉本專案架構（含新手）。共用原則見 [`_shared/fe-mr-common/review-writing-principles.md`](../../_shared/fe-mr-common/review-writing-principles.md) 與 SKILL.md「報告撰寫風格（核心）」——先講脈絡再講問題、每個 finding 配關鍵程式碼、白話先行（第一次術語用「中文 (English)」）、複雜術語放該 finding 末的名詞補充、商業邏輯比喻只放摘要。

```markdown
## Code Review 摘要

**這次改動在做什麼**: [比喻]（就像…）／[技術]（一句精確描述）
**變更規模**: [小型/中型/大型]（[N] 行）
**整體評估**: [分數]/10 - [一句話理由]

---

## 需要改進

### [問題 1 標題（用白話描述現象，不用術語當標題）]
- **來源**: [工具 / agent 名稱]
- **嚴重度**: [Critical/High/Medium/Suggestion]
- **位置**: [`檔案:行號`](連結；審 MR 時附 GitLab 行號連結)
- **程式碼**:
  ```tsx
  // 只貼關鍵 3–5 行，省略處用 // …
  ```
- **背景**: [這段程式在做什麼、涉及什麼脈絡；若牽涉既有架構，先簡述該架構在做什麼、為何存在]
- **問題**: [哪裡不對 + 會造成什麼具體後果（如「使用者連點兩次會送出兩筆訂單」）]
- **建議**: [具體、可執行的改進方式]

<details>
<summary>學習點：為什麼這是問題</summary>

[背後原理說明，讓讀者下次能自己看出同類問題；可含改進後程式碼範例]

</details>

> **名詞補充**（若本 finding 出現新手會卡的複雜術語才加；一般常識字不收）
> - **[術語 (English)]**: [一句話：是什麼、為什麼重要]

---

## 注意事項

- [潛在風險或未來考量，同樣用白話說明]

---

## 👤 需人工確認

> 程式碼無法自動判斷、需人親自確認的點。

- [ ] **[檢查項標題]** `(需資深經驗 | 新手可略過)`
  - **動作**: [去哪、做什麼]
  - **預期**: [看到什麼才算對]
  - **為什麼重要**: [不確認會有什麼風險]
  - **驗證方式**: [手動操作 / 看 log / 跑某指令 / 問 PD…]

---

## 確認項目

- ✅ [AI 已確認功能正常項目]
- ✅ [測試通過項目]
```

> 術語不集中到報告末，改用「白話先行 + 第一次術語『中文 (English)』」處理；需展開的複雜術語放在該 finding 末的「名詞補充」（見上方 finding 模板）。
