# 逐則回覆 reviewer 留言

每則留言在自己的討論串下各自回覆，不合成一筆總回覆。語氣客氣、交流，不指責也不反駁。

## 三條硬規則

1. **開頭先感謝**：「感謝發現，這確實是個問題，……」或「感謝建議，……」
2. **句尾不展開**：事實講完就收。嚴重度分析、寫法對照、設計脈絡、重現步驟都放在 review-triage 報告、修正 commit 的 body 或票裡，不貼進回覆
3. **不徵詢 reviewer**：不問對方同不同意，也不提供「或者我先補個短期防護」這類選項。結尾二選一：「已在 `<commit>` 修正」或「已開票處理 #N」

## 依判定的寫法

| review-triage 判定 | 回覆 |
|---|---|
| 確認，在這張 MR 修 | 感謝發現，這確實是個問題，＜一句話講問題＞。已在 `<commit>` 修正。（一類的話補一句「同類寫法另有 N 處一起改了」） |
| 確認，另開票 | 感謝發現，這確實是個問題，＜一句話講問題＞。已開票處理 #N。 |
| 防禦性建議 | 感謝建議，＜一句話講要加強什麼＞。已開票處理 #N。 |
| 撤銷 | 感謝提醒。＜一兩句講原本的設計與流程＞。不說「你讀反了」，可以說可能是自己沒寫清楚 |
| 提問 | 直接回答，一兩句講完 |
| 待驗證 | 結論出來前只回「感謝，我先重現看看」 |
| 質疑前提 | 等使用者決定保留或推翻後，再照上面的寫法回 |

## 注意

- 引用了 commit hash 之後，就不要再 amend 或 rebase 那個 commit；要補就加新 commit
- 發完要用獨立查詢確認 note 真的建立（見 SKILL.md「Review comment 是 individual note」）
